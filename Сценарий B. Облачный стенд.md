# Сценарий B. Облачный стенд

Для обучающихся без физического комплекта.

Платформа эксплуатирует пул из **20 плат Raspberry Pi Pico** с датчиками и дисплеем. Стенд физически располагается в МФТИ, сервер платформы подключается к нему через VPN или SSH reverse tunnel. Обучающийся загружает скомпилированный `.uf2`, платформа прошивает плату, запускает тест-сценарий и возвращает результат с логом.

## Идентификация прошивки

Каждый обучающийся вкомпилирует в прошивку `student_token` (публичный числовой идентификатор) и `BUILD_TIMESTAMP` (Unix-время сборки). Оба значения показаны в заданиях курса через два разных механизма — как учебный материал по системам сборки.

**Вариант 1 — через `#define` в заголовочном файле** (ранний модуль):
```c
// student_config.h
#define STUDENT_TOKEN  0x0000A42F
```

**Вариант 2 — через аргумент cmake `-D`** (поздний модуль):
```cmake
string(TIMESTAMP BUILD_TIMESTAMP "%s")
target_compile_definitions(firmware PRIVATE
    STUDENT_TOKEN=${STUDENT_TOKEN}
    BUILD_TIMESTAMP=${BUILD_TIMESTAMP}
)
```

Стенд читает оба значения через команду `fw_info` и проверяет:
- `student_token` совпадает с токеном обучающегося в БД
- прошивка собрана не более **15 минут** назад (достаточно для сборки даже на слабом ПК)

`student_token` — публичный идентификатор, не является секретом. `secret_key` для HMAC никогда не попадает в бинарник — см. [[HMAC и токены]].

## Инфраструктура стенда

```
Управляющий ПК в МФТИ
    ├── Очередь задач (Redis + Celery)
    ├── Flasher (picotool)
    └── USB Hub
          ├── Pico #1 + BME280 + ILI9341
          ├── Pico #2 + BME280 + ILI9341
          └── ... (20 плат)
```

При 500 обучающихся и времени теста 30–60 сек ожидание в очереди составит 1–2 минуты в штатном режиме. Пиковые нагрузки — перед дедлайнами.

**Правило зачёта:** CI passed И токен совпал И прошивка ≤ 15 мин И все тесты стенда прошли.
