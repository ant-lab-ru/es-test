# HMAC и токены

У каждого обучающегося два значения:

| | `student_token` | `secret_key` |
|---|---|---|
| Что это | Публичный числовой ID | Секретный ключ подписи |
| Где хранится | БД платформы + бинарник | ПК обучающегося + БД платформы |
| Назначение | Идентификация прошивки | Подпись HMAC отчётов |
| Попадает в бинарник | ✅ да | ❌ никогда |

**Как работает подпись.** Агент формирует JSON-отчёт, вычисляет `HMAC-SHA256(secret_key, json_payload)` и отправляет подпись вместе с отчётом. Платформа вычисляет ту же подпись на своей стороне и сравнивает через `hmac.compare_digest`. При несовпадении — запрос отклоняется.

```python
# На стороне агента
payload = json.dumps({...}, sort_keys=True).encode()
signature = hmac.new(secret_key, payload, hashlib.sha256).hexdigest()
```

**Что это даёт:** содержимое отчёта не изменено по дороге; отчёт точно сгенерирован агентом, знающим ключ обучающегося.

**Ограничение:** обучающийся теоретически может модифицировать `pico-check` и генерировать фальшивые отчёты с правильной подписью. Для взрослой профессиональной аудитории это приемлемо — человек, способный написать такой обход, уже владеет материалом курса.
