# Сценарий D. Конструктор спутника

Финальное задание курса — подключение собранного прибора к реальному бортовому оборудованию.

## Контекст

В МФТИ физически расположены 5 конструкторов спутника (бортовой компьютер, система питания, датчик ориентации). Каждый подключён к управляющему ПК через USB-CAN преобразователь. Обучающийся собирает прибор-финалист на Raspberry Pi Pico с поддержкой сетевой адресации и отправляет телеметрию (температура МК, давление BME280) на борт конструктора. В каждом пакете содержится `student_token`.

## Сетевая архитектура

Туннели на ПК обучающегося не используются — заменены на WebSocket. Соединение работает через любой NAT и корпоративный firewall.

```
Прибор обучающегося (Pico)
    │ COM / USB serial
pico-check connect --task 5.2 --port COM3
    │ WebSocket (wss://, порт 443)
WebSocket-прокси сервер в МФТИ (белый IP)
    │ программный CAN-адаптер
USB-CAN преобразователь
    │ CAN-шина
Конструктор спутника (бортовой компьютер)
```

## CAN-адресация по токену

Каждый прибор получает уникальный CAN ID, производный от `student_token`:
```c
uint16_t can_id = STUDENT_TOKEN & 0x7FF;  // 11-битный CAN ID
```

Программный CAN-адаптер транслирует WebSocket-пакеты в CAN-кадры с соответствующим ID. Телеметрия от всех обучающихся разделяется на шине автоматически.

При частоте телеметрии ≤ 1 Гц и 500 обучающихся нагрузка на шину составляет ≤ 100 кадров/сек на конструктор — стандартная шина 500 кбит/с выдерживает с многократным запасом.

Программный CAN-адаптер используется в курсе также как демонстрация имитатора устройства — дидактически ценный пример для занятия по интерфейсам.

## Grafana

Для преподавателей и администраторов — полноценные дашборды с телеметрией бортовых систем. Для обучающихся — общедоступный дашборд с агрегированной телеметрией конструкторов, как демонстрация «как выглядит мониторинг реального КА». Кастомные дашборды для отдельных обучающихся не создаются.

Для проверки задания — виджет в личном кабинете: «Телеметрия подключена» (зелёный/красный) + последние N принятых пакетов от прибора. Обновляется в реальном времени.

## Проверка задания

Платформа читает базу телеметрии (InfluxDB / TimescaleDB) и ищет ≥ 10 пакетов с корректным `student_token` за последние 30 минут текущей сессии. 10 пакетов при 1 Гц = 10 секунд стабильной передачи.

Rate limiting: не более 2 пакетов/сек с одного токена. После достижения порога зачёта запись новых пакетов от этого токена по данному заданию прекращается.

Конструкторы работают круглосуточно, доступ без расписания. Формат пакета телеметрии предоставит МФТИ (согласование до начала курса).

**Правило зачёта:** CI passed И ≥ 10 пакетов телеметрии с `student_token` за последние 30 мин.
